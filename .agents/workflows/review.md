# Review Workflow

## Output

- 지적 사항을 심각도순으로 제시하고 각 항목은 파일·줄 번호·실제 영향에 근거합니다.
- 문제가 없으면 명확히 말하고 남은 테스트 공백이나 잔여 위험을 적습니다.
- 테스트 누락은 구체적 동작 위험이 있으면 지적 사항으로, 단순 미실행이면 잔여 위험으로 적습니다.
- 요약·질문·변경 제안은 지적 사항 뒤에 둡니다.

## Procedure

1. 대상 파일의 현재 내용과 diff를 중심으로 보고, 인접 파일은 계약 확인에 필요한 범위만 읽습니다.
2. `.agents/index.md`에서 작업에 맞는 문서를 추가로 선택합니다.
3. 버그, 동작 회귀, 데이터 손실, 책임 경계 위반, 위험한 모호성을 먼저 찾습니다.
4. 선택한 문서에서 변경에 영향받는 섹션을 균등한 깊이로 확인합니다.
5. 하네스 문서 리뷰는 `.agents/rules/harness-doc.md`를 기준으로 확인합니다.
6. compile·import·test·문서 검증 여부가 변경 위험도에 맞는지 확인합니다.

## Boundaries

- 리뷰 중에는 파일을 수정하지 않습니다(무단 수정 금지 규칙은 `.agents/core.md`). 수정 요청을 받으면 implement workflow로 전환합니다.
